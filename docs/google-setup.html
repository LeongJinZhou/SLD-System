Connect QIU Google sign-in

The sign-in integration needs a QIU-owned Google OAuth client. Set it up once, then launch this prototype with its credentials. The full local guide is docs/GOOGLE_SETUP.md in the project.

1. Create the Google client

  1. Open Google Cloud Console with the QIU account that manages the project. Create or select a university-owned project.
  2. Under Google Auth Platform → Branding, enter “QIU Student Life Division” and your support/developer contacts.
  3. Under Audience, choose Internal for QIU's Workspace organization. Ask QIU IT if Internal is unavailable. An authorized external testing project requires its QIU test users to be listed.
  4. Under Clients, create a Web application client. Set the origin to http://127.0.0.1:8765 and the redirect URI to http://127.0.0.1:8765/auth/callback.
  5. Download the client JSON and keep it in a private local folder outside this project.

Reference: Google OAuth setup and consent-screen setup.

2. Start the configured prototype

Close the existing server terminal first. Open PowerShell in the project directory and run the following, replacing the private path and SLD email with your own values:

.\tools\start_google.ps1 -ClientJson 'C:\private\qiu-sld-client.json' -AdminEmails 'your.sld.account@qiu.edu.my'

The launcher reads the secret locally without printing or saving it. Open http://127.0.0.1:8765/. Google sign-in appears above seven fictional test roles. Use the exact 127.0.0.1 address; localhost is a different host.

This local prototype uses the test database, even when Google identity is verified. Keep real student and financial data out of it. Do not paste your secret into chat or the website. The launcher’s -OfficialMode disables test roles and selects the separate official database; production hosting/readiness still needs review.

3. Enable directory capture

Enable People API in the same Cloud project. Add https://www.googleapis.com/auth/directory.readonly under Data Access. QIU IT must allow the app, scopes and university directory sharing. Restart with -Directory:

.\tools\start_google.ps1 -ClientJson 'C:\private\qiu-sld-client.json' -AdminEmails 'your.sld.account@qiu.edu.my' -Directory

Sign in again. Your own available profile can be captured. Mixed prototype contact searches/imports remain fictional fixtures. To test the real QIU contact directory, stop the server and add both -Directory and -OfficialMode to the launcher command. That selects the separate official-mode database and disables fictional test-role buttons; it remains local verification, not a production deployment.

.\tools\start_google.ps1 -ClientJson 'C:\private\qiu-sld-client.json' -AdminEmails 'your.sld.account@qiu.edu.my' -Directory -OfficialMode

Missing profile fields stay unavailable. Directory titles do not make someone an SLD administrator. Only the configured SLD email allowlist grants that role. Google directory access guide.

4. Verify

  • Your QIU account shows Google verified identity; personal Gmail is rejected.
  • Your allowlisted SLD account sees the SLD dashboard.
  • With Directory enabled, search for a known student and check the returned identity fields. SLD can import visible contacts.
  • Test buttons remain labelled as fictional prototype users.

No live Google connection has been verified on this machine yet.

If it fails

  • redirect_uri_mismatch: check the exact callback and 127.0.0.1 host.
  • Access blocked: ask QIU IT to allow the app or correct its Audience/test users.
  • Directory unavailable: check People API, scope and QIU sharing policy; sign in again.
  • Port in use: close the existing server. Only one can run on port 8765.
